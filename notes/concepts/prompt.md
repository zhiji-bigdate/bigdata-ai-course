## 4. 结构化解释（Structured Explanation）

### 4.1 一句话定义（Definition）

**Prompt 是你发给大模型的一段文字指令，用来告诉它"你想要什么、按什么标准、用什么格式回答"。**

### 4.2 直观类比（Intuition）

把大模型想象成一位**刚入职、能力很强但完全不了解你的新同事**。

- 你跟他说"帮我弄一下那个报告"，他一脸懵，只能猜——这就是**模糊的 Prompt**。
- 你跟他说"帮我整理这份采访录音，把里面提到的三个数据点摘出来，用表格列成三行，第一列是数据、第二列是出处、第三列是原话"——他马上就能干，这就是**清晰的 Prompt**。

同事能力没变，变的是你**交代任务的清晰程度**。Prompt 工程，本质就是学会"怎么把话说清楚"。

### 4.3 机制原理（Mechanism）

**大模型不是"读心者"，它读的是"文字序列的概率"。** 你输入的每一个字，都会被拆成 token（词元），送进模型里参与一次"预测下一个词"的计算。Prompt 的作用，就是**给这次预测一个明确的方向**。

具体来说，一条好的 Prompt 通常靠这几个要素起作用：

1. **角色（Role）**——"你是一位资深财经记者"，会让模型在生成时更倾向于使用专业、克制的表达，而不是网上论坛的口吻。这不是"赋予身份"，而是**改变了它采样的概率分布**。
2. **任务（Task）**——明确要"做什么"，把模糊的"帮我看看"变成"总结成三点"。
3. **上下文/背景（Context）**——把模型不知道的信息喂进去，比如"这篇稿子是关于台风'海葵'的"。
4. **约束与格式（Constraints & Format）**——"用 100 字以内""输出成 JSON""分三段"，直接规定产出的形状。
5. **示例（Few-shot）**——给一两个"输入→输出"的示范，模型会照着这个模式继续，效果往往比干巴巴描述规则更好。

这些要素不是越多越好，而是**越贴合当前任务越好**。

### 4.4 边界与误区（Boundaries）

Prompt 能改变方向，但**不能突破模型本身的能力上限**。以下是最常见的几个误区：

- **误区 1：「Prompt 越长越好」**。其实冗余信息会稀释重点，还可能触发"中间信息被忽略"（Lost in the Middle）的问题。精准比冗长重要。
- **误区 2：「加一句'请认真回答/你是专家'就能让它变强」**。这类空话对概率分布影响很弱，远不如给出**具体的角色 + 具体的任务 + 具体的格式**有效。
- **误区 3：「Prompt 是一次性的，问完就没了」**。好的 Prompt 可以沉淀成模板、甚至封装成 Skill，反复复用（这正呼应了「Skill」这个概念）。
- **误区 4：「Prompt 就是代码」**。它不是编程语言，没有严格的语法，靠的是自然语言表达的清晰度。

## 5. 应用案例（Application Cases）

### 案例 A：真实场景——Claude / ChatGPT 的系统提示词

在 ChatGPT、Claude、以及你正在用的 WorkBuddy 里，背后都有一条「系统提示词（System Prompt）」。它是一段写死的 Prompt，用来规定这个 AI 的**身份、行为边界、输出风格**。比如"你是 WorkBuddy，一个中文友好的编程助手，遇到不确定的事要先查证"。这就是 Prompt 在真实产品里最硬核的应用——它决定了 AI 的"人设"。

### 案例 B：课堂练习——亲手对比两种问法

打开你电脑上的任意一个大模型对话（豆包、ChatGPT 都行），做一个小实验：

1. 先问模糊版："写点关于台风的。"
2. 再问清晰版："你是一位地方都市报记者，请写一条 80 字以内的短消息，报道台风'海葵'今晚登陆，需包含登陆时间、地点、预计风力，语气客观，不要标题党。"

对比两次输出。你会发现清晰版直接就能用，模糊版要来回追问好几次。**这个差距，就是 Prompt 的价值。**

## 6. 概念辨析（Concept Disambiguation）

- **Prompt vs 上下文（Context）**：Prompt 是你这一次输入的指令；上下文（Context）是模型这轮"能看到的一切"的合集，Prompt 只是其中最新的一部分。Prompt 是"你刚说的话"，上下文是"它脑子里此刻装的全部"。
- **Prompt vs 问题（Question）**：问题只是 Prompt 的一种形态（"X 是什么？"）；Prompt 还可以是命令、是带格式要求的任务说明、是带示例的模板。Prompt 是更上位的概念。
- **Prompt vs Skill**：Prompt 是一次性输入，用完即止；Skill 是"把一类好 Prompt 沉淀成可复用的工作说明书"，跨任务反复加载。可以理解成——**好的 Prompt 被固定下来、长期维护，就成了 Skill**。

## 7.5 选择题练习（Multiple Choice with Feedback）

<details>
<summary>点击展开 5 道选择题（先自己做，再看答案）</summary>

**第 1 题：以下哪一项，最能描述 Prompt 的本质？**

A. 一种严格的编程语言
B. 一段用来引导大模型输出方向的自然语言指令
C. 大模型内部的一个模块
D. 只有 ChatGPT 才有的功能

- A 错：Prompt 靠自然语言表达，没有严格语法，不是编程语言。
- B **对**：Prompt 的本质就是"引导输出的文字指令"。
- C 错：Prompt 是"输入"，不是模型内部零件。
- D 错：几乎所有大模型都吃 Prompt，不是某一家独有。

> **考点**：Prompt 的定位——它是外部输入，不是模型的一部分。
> **你如果选了 C**：说明你把它当成了模型"身体里的器官"，其实它是你递给模型的"纸条"。

**第 2 题：下面哪条 Prompt 最可能得到"直接能用的新闻短消息"？**

A. "写点关于台风的。"
B. "你是一位都市报记者，请写一条 80 字以内的短消息，报道台风今晚登陆，含时间、地点、风力，语气客观。"
C. "请认真、仔细、专业地回答我关于台风的问题。"
D. "台风。"

- A 错：太模糊，模型只能猜。
- B **对**：角色+任务+字数+要素+语气全都说清了。
- C 错："认真/仔细/专业"是空话，没告诉它具体要什么。
- D 错：只有一个词，信息严重不足。

> **考点**：好 Prompt = 具体要素齐全，而不是堆形容词。
> **你如果选了 C**：你被"礼貌用语"迷惑了——真诚的形容词不等于清晰的指令。

**第 3 题：Prompt 和"上下文（Context）"是什么关系？**

A. 完全是一回事
B. Prompt 是上下文的一部分（通常是最新输入）
C. 上下文是 Prompt 的一部分
D. 两者毫无关系

- A 错：上下文范围更大，Prompt 只是其中一块。
- B **对**：上下文 = system prompt + 历史 + 工具返回 + 当前 Prompt 的合集。
- C 错：方向反了。
- D 错：Prompt 直接参与构成上下文。

> **考点**：Prompt 与 Context 是"部分与整体"的关系。
> **你如果选了 C**：把包含关系记反了，记住"上下文是更大的那个筐"。

**第 4 题：把好 Prompt 沉淀成长期可复用的模板，这更接近哪个概念？**

A. Skill
B. 变量
C. 缓存
D. 报错

- A **对**：Skill 正是"把某类任务的最佳 Prompt/流程固定下来反复用"。
- B 错：变量是编程概念，和沉淀 Prompt 无关。
- C 错：缓存是临时存储，不是"沉淀方法论"。
- D 错：完全无关。

> **考点**：Prompt（一次性）→ Skill（长期复用）的演进关系。
> **你如果选了 C**：缓存是"临时存结果"，Skill 是"存方法"，别混淆。

**第 5 题：关于 Prompt 的说法，哪一项是"误区"？**

A. Prompt 越长一定越好
B. 好的 Prompt 要贴合具体任务
C. 给一两个示例（Few-shot）常常很有效
D. Prompt 是自然语言，不是代码

- A **是误区**（本题选它）：冗余会稀释重点，精准比冗长重要。
- B 对：贴合任务是好 Prompt 的核心。
- C 对：示例能显著提升效果。
- D 对：这是正确认知。

> **考点**：识别"越长越好"这个最普遍的 Prompt 误区。
> **你如果选了 B/C/D**：说明你已经理解了正确做法，只是没注意题目问的是"误区"。
